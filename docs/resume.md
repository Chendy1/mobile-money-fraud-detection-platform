# Resume and profile text (Phase 26)

Bullets you can paste, each tied to something in the repository, and the rules that keep them true. A test (`tests/unit/test_portfolio_unit.py`) checks that every figure in the bullets appears in the claims ledger below, that each ledger figure is found in its source file, and that none of the banned phrases appear.

## Rules
1. **Only what is implemented.** Every bullet maps to a row in "Evidence for each bullet". If a thing is design-only or unverified, the bullet says so in the same sentence.
2. **Every number has a source.** No figure goes in a bullet unless it is in the claims ledger with the file it comes from.
3. **Say "synthetic".** The data is generated by this project. No bullet claims results on real customers, real fraud, real money, an employer, or a user base.
4. **Say "assumed" where costs appear.** Costs and thresholds are assumptions; the 46% below is a statement about them.
5. **Pick four to six bullets for one resume**, matched to the role (sets below). More is padding.

## Bullets
<!-- bullets:start -->
**Machine learning and data science**
- **B1** Built an end-to-end fraud-risk scoring pipeline on a synthetic M-Pesa-style dataset of 200,000 transactions with delayed, noisy labels (fraud reported up to 45 days late; 10.7% of fraud-labelled rows not truly fraud), using a time-based split with a label gap so no training row uses a label that was unknown at the time.
- **B2** Compared hand-written rules, logistic regression, a random forest and LightGBM using PR-AUC with customer-level bootstrap intervals, and reported that the learned models could not be separated on about a hundred test-window frauds (LightGBM did not beat the random forest) instead of claiming a winner.
- **B3** Implemented 28 point-in-time-safe features in one library shared by training and the scoring API, and showed there is no training/serving skew by replaying 300 held-out transactions through the API (zero difference from batch probabilities, same actions), alongside truncation (leakage) tests.
- **B4** Calibrated scores (Platt scaling) and turned them into ALLOW, REVIEW or BLOCK with an expected-cost rule under explicit, assumed costs; under those assumptions expected cost was 46% below allowing everything, with a sensitivity table showing how the ranking of models changes with the assumptions.

**Data engineering**
- **B5** Built a layered Parquet and DuckDB data lake (immutable raw layer, cleaned layer, quarantine with a reason per rejected row, ingestion ledger) with two-tier data-quality checks and a reproducible EDA report in which every number is computed from the lake.
- **B6** Wrote a streaming simulator (bounded queue, reorder buffer, seeded faults: jitter, duplicates, corrupted events) with an accounting check that every event ends scored, rejected or dropped.

**MLOps, security and platform**
- **B7** Served the model through a FastAPI service with strict input validation, hashed API keys with roles, TLS, per-key rate limits and an audit log, and wrote an outside-in verifier for those boundaries: 12 checks, all passing against the Docker container on my machine.
- **B8** Added drift detection (population stability index against a frozen validation-window reference, shown firing on a deliberately shifted week, with its blind spot measured and documented) and gated retraining behind a file-based model registry with explicit, reasoned promotion.
- **B9** Built an open-loop load tester that counts latency from when each request was due, so a slow server cannot hide its own queueing, and used it to measure one scoring process on a 2-CPU machine.
- **B10** Hardened a Docker Compose deployment (read-only filesystems, dropped capabilities, secrets as files, preflight rules read from the compose file itself) with backup and restore that checks a SHA-256 manifest before writing anything.
- **B11** Set up GitHub Actions with four jobs (lint and more than 1,100 automated tests, image builds, Terraform validation, dependency audit), and diagnosed and fixed a CI failure that had kept the build red for five consecutive pushes.

**Cloud (design only)**
- **B12** Designed an AWS deployment (ECS Fargate in private subnets, no public endpoint) as plan-only Terraform that passes `terraform validate` in CI but was never applied, with a cost estimator that uses prices read from AWS pages and gates the hourly-billed VPC endpoints; 29 architecture decision records record the trade-offs.

## Banned wording
Do not write any of these, in the bullets or elsewhere. The first three are the ones people drift into without noticing.
- "Deployed to AWS" or anything implying cloud operation. It is plan-only and was never applied.
- "In production", "production-grade", "real-time at scale". It is a local simulation measured on one machine.
- "Reduced fraud losses", "saved", "increased accuracy by X%", or any money or percentage outcome not in the ledger. The 46% is under assumed costs and must say so.
- "Real customers", "real transactions", "M-Pesa data", "Safaricom". The data is synthetic and the project is not affiliated with Safaricom.
- "State-of-the-art", "best model", "outperforms". LightGBM did not beat the random forest here.
- "Tested on Windows" for the demo, backup and restore, or the full suite. Not reported.
