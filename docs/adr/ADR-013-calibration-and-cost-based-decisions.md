# ADR-013: LightGBM chosen on validation, Platt calibration, and decisions from an expected-cost rule
**Context.** Phase 7 produced scores that rank fraud, but a score is not a decision. Three things are missing: a stronger model to compare with the baselines, probabilities that can be priced, and a rule that turns a probability and an amount into an action. The costs of a review or of blocking a good customer are not known for this simulation, and the test window holds only about a hundred fraud cases.
**Decision.**
- Train LightGBM with the same discipline as the baselines: settings (leaves, minimum rows per leaf, class weight) and the number of boosting rounds are chosen on the validation window only. There is no early stopping, because that would let the training step look at validation rows. The test window is scored once, after every choice.
- Calibrate every scorer with Platt scaling (a two-parameter logistic curve), fitted on the validation window only. Rules, which output a count of fired rules, use the score itself as the input; models use the logit of the score. Calibration error and Brier score are reported on the test window, with a reliability table that shows groups with no fraud rather than hiding them.
- Turn probabilities into one of three actions by expected cost: ALLOW (risk level LOW), REVIEW (MEDIUM) or BLOCK (HIGH). ALLOW costs p x loss x amount; REVIEW costs the review cost plus the fraud a review does not stop; BLOCK costs (1 - p) x the friction cost. The lowest expected cost wins; a tie goes to the less severe action. No label is read when deciding.
- The costs are assumptions held in one frozen `CostModel` (loss rate 1.0, review 25 KES, review stops 70% of fraud, block friction 150 KES) and are printed as assumptions wherever they appear. Every cost result comes with a sensitivity table (costs 0.25x to 4x, and review effectiveness 50% to 90%), a bootstrap interval that resamples whole customers, a comparison with a fixed 0.5 cut-off, and a perfect-knowledge floor.
- Ship the decision path as one object, `RiskModel` (scorer, calibrator, cost model, feature version), saved as a joblib file plus a readable JSON file that marks the cost values as assumed. Phase 11 will serve this object.
- An optional audit uses the hidden ground truth to show what the observed labels missed. Nothing in it feeds back into training, calibration or decisions.
**Alternatives.** Isotonic calibration (needs more positives than this window has; steps on few cases); one global probability threshold (ignores that a large transaction justifies a lower threshold than a small one); optimising F1 (hides the cost of each error type); choosing costs to make a result look good (rejected: costs are inputs, reported with sensitivity); early stopping on validation (leaks validation into fitting); a bigger grid or a different library to find a gap over the random forest (the result is reported as it is).
**Consequences.** On this synthetic data LightGBM did not beat the random forest on ranking; the paired difference includes zero. Its cost under the assumed costs has the lowest point estimate, but the interval overlaps the other learned scorers and the ordering changes with the assumed costs, so the report says no scorer is best without real cost figures. The cost rule did beat a fixed 0.5 cut-off. Limits: one validation window fixes the calibration, and the test window has a lower fraud rate, so calibration drift is expected and is a Phase 14 topic; reviews and blocks are modelled with fixed shares and ignore queues, delays and capacity; the loss is a fixed share of the amount; the author saw one LightGBM test score while building the code, and the report says so. The Platt fit adds two parameters per scorer, which a validation window of this size supports.
