# ADR-012: Time-based split with a label gap; PR-AUC, review budgets and customer bootstrap
**Context.** A fraud model is judged on future transactions, and its labels arrive late: fraud is reported up to 45 days after the fact and legitimate transactions are only confirmed after 45 days. Random splits put one fraud episode on both sides, accuracy is meaningless at a 0.5% fraud rate, and a test set with about a hundred fraud cases gives noisy metrics that are easy to over-read.
**Decision.**
- Split by time. Counted back from the end of the data: the last 45 days are never evaluated (labels incomplete); test is the 45 days before that; validation the 45 days before test; training ends 45 days before validation starts. The model is imagined to be deployed on the validation start date, so training uses only transactions old enough to have confirmed labels and only the labels known on that date. Validation and test rows are scored against their final labels.
- Fit everything that is learned (imputation values, scaling, model weights) on the training rows only. Feature matrices are built by a stateless function with fixed category vocabularies, so building them cannot learn from the data it sees.
- Primary metric PR-AUC (a random scorer scores the fraud rate), plus precision and recall at fixed review budgets (alerts per 10,000 transactions). Tied scores are handled in proportion, so a rule engine's many ties are neither helped nor hurt by row order. Accuracy is not reported; ROC-AUC is secondary.
- Intervals come from a bootstrap that resamples whole customers, because a customer's transactions and a fraud episode are not independent. Models are compared on identical resamples, and differences are reported with their own interval.
- The baseline ladder is no skill, hand-written rules (fixed thresholds from the EDA, never fitted), logistic regression and a random forest. Settings are chosen on validation; the test part is scored once by the run, after selection.
- The run also refits the chosen settings with no gap and final labels for every training row, and reports the change in scores, so the effect of the shortcut is measured rather than asserted.
**Alternatives.** Random or stratified k-fold (leaks episodes and the future); a single global threshold metric such as F1 (depends on an arbitrary cut-off; cost-based thresholds come in Phase 8); row-level bootstrap or a normal approximation (too narrow when rows are clustered); calibration and class weights as defaults (class weights lowered PR-AUC here, see the report).
**Consequences.** Scores are honest about time and label delay, and the report says when two models cannot be told apart. Costs: the gap and the unevaluated tail discard about 40% of the year; the test part holds about a hundred fraud cases, so intervals are wide (about +/-0.12 on PR-AUC); the evaluation covers existing customers only; one validation window with a small grid is a weak basis for tuning; the shortcut check showed a small effect on this synthetic data, so the gap is justified by what is knowable in reality and not by this dataset's scores; the author looked at test scores during development (no setting was changed on that basis), which the report states. Models are not calibrated and no decision threshold is set; that is Phase 8.
