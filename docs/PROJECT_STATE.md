- **Streaming (ADR-018):** `mmrisk.streaming`: `python -m mmrisk.streaming run|summary`. Lake transactions are replayed as events: seeded faults (jitter, repeats, corrupted copies), a producer thread and a bounded queue (backpressure measured), a watermark reorder buffer (`--max-lateness`; late and repeated events dropped and counted), one consumer scoring in process (`LocalScorer`) or over HTTP (`HttpScorer`, `--url`, needs `--from` and an API started with the same `--history-until`, or `MMRISK_HISTORY_UNTIL`). Every event is scored, rejected or dropped and the report says whether the books balance (exit 1 if not). Append-only Parquet prediction store `data/predictions/part-NNNNNN.parquet` (14 columns, `docs/prediction-store.md`), refuses a non-empty store without `--append`. Compose gets a `simulator` service (profile `simulate`, `STREAM_FROM`). Sandbox results on the default dataset, last 7 days (4,698 events), in process: all scored; ALLOW 4,569, REVIEW 91, BLOCK 38 (2.75% flagged); scorer latency p50 4.2 ms, p95 7.2 ms; about 206 scored per second; queue full (1000 of 1000) with the producer waiting 0.77 s. Over HTTP with faults on (1,500 events, 2% repeats, 1% corrupted, jitter 20 s, lateness 30 s): 1,500 scored, 24 repeats dropped by the buffer, 21 corrupted rejected, 0 late, about 123 per second. Key test: a clean stream, and a messy one with enough lateness, give the same probabilities (within 1e-12) and actions as batch scoring; with lateness 0 events are lost.
