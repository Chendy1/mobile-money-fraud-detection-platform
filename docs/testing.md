# Testing
- Framework: pytest. Linting and formatting: ruff.
- Layout: `tests/unit`, `tests/integration`, `tests/data`, `tests/api`.
- Run on Windows: `.\scripts\dev.ps1 test` and `.\scripts\dev.ps1 lint`. Linux/macOS: `make test`, `make lint`.
- CI (`.github/workflows/ci.yml`): ruff check, ruff format check, pytest with coverage. No cloud credentials.
- Rule: each phase adds tests, including failure-path tests. Coverage is monitored, not chased.

## Phase 2 tests
- `tests/unit/test_generation_config.py`: config validation, probability tables, CLI behaviour.
- `tests/data/test_generated_data.py`: row count and exact fraud rate, schema, referential integrity, no fraud columns in observable tables, noisy and delayed labels, overlap of every fraud signal with legitimate behaviour, no perfect single-signal rule, device-id leakage, determinism for a given seed.
- Tests were checked by mutation: breaking the generator on purpose (perfect labels, a leaked fraud column, no legitimate new-device events, unpermuted device ids) makes the relevant test fail.
- Coverage is monitored, not chased.

## Phase 3 tests
- `tests/unit/test_ingestion_units.py`: table specs, validation gates (cast failures, nulls, blanks, fractional amounts), standardisation, deduplication, atomic writes, ledger.
- `tests/integration/test_ingestion_pipeline.py`: end to end on generated data. Covers idempotent re-runs, replays under a new file name, identical lakes from identical input, rebuild after a lost ledger, a simulated crash mid-batch (unfinished data stays invisible and the re-run matches a clean run), overlapping batches with duplicates, conflicts, null keys and unparseable amounts, whole-batch rejection (missing column, extra column, unreadable file), dimension snapshots, ground truth never entering the lake, reconciliation detecting a deleted partition or tampered raw file, and CLI exit codes.
- Mutation-checked: disabling deduplication, the ledger skip, the null-key gate, or batch visibility each makes specific tests fail.

## Phase 4 tests
- `tests/unit/test_dq_rules.py`: every domain rule fires on a violating row and stays silent on a valid one (a guard fails if a rule has no test); configuration is checked against the generator's reference data so the two cannot drift apart.
- `tests/data/test_data_quality.py`: the data is deliberately corrupted in specific ways and the test asserts the right quarantine reason or check result. Covers 11 row defects, threshold boundaries (quarantine, duplicates, conflicts, orphans), dtype drift, a rejected batch followed by a fix, nulls and duplicates injected into stored files, a deleted partition, labels known before their transaction, freshness, missing days, a volume spike, tiny datasets, the JSON report and CLI exit codes.
- A dedicated test asserts that freshly generated data produces no WARN and no FAIL (no false positives).
- Mutation-checked: neutering a rule, making the referential or label-timing check never fail, over-strict category rule, and a raised threshold each make specific tests fail.
- The full suite takes roughly 1.5 minutes on a single core (it builds many small lakes); expect a few minutes on a slower laptop.

## Phase 5 tests
- `tests/integration/test_eda.py` builds a small dataset, ingests it and checks the analysis layer.
- **Brute-force cross-check:** `prior_n`, `prior_avg`, `secs_since_prev` and `n_10min` are recomputed with plain Python loops for a sample of customers and must match the DuckDB window results.
- **Leakage:** dropping each customer's later rows must not change any earlier row's features; a global time cut must not change the "last inbound transfer" feature. Mutation-checked: including the current row in a window, a window that looks forward, and a reversed ASOF join each make a test fail.
- Signal table bounds, class balance on matured rows only, hidden recent labels, Spearman symmetry, Wilson interval, the report (7 figures, computed numbers, audit present or skipped), an empty lake raising a clear error, and the CLI exit codes.
- The EDA tests are skipped if `duckdb` or `matplotlib` is missing; install with `pip install -e ".[dev,eda]"` (`dev.ps1 setup` does).

## Phase 6 tests
- `tests/unit/test_features_unit.py`: every feature checked by hand on tiny frames with known answers, including boundaries (a cash-out at exactly 7,200 s and at 7,201 s; a transaction exactly 10 minutes earlier), same-timestamp ties, history that is too short, inputs in any order, bad input, and the audit's AUC and planted-leak detection.
- `tests/integration/test_features.py` builds a small dataset and checks: a global time cut and a per-customer cut leave earlier rows' features unchanged (leakage); shuffled input gives identical output; 500 sampled transactions streamed through the online path match the batch features; the Polars features equal the independent DuckDB definitions from Phase 5 exactly; the training table contains only labels known at the chosen time and never treats recent unlabelled rows as legitimate; features do not change with the label time; no single feature separates the classes suspiciously well; the CLI is deterministic; the committed feature catalog matches the registry.
- Mutation-checked: a window that includes the current row, an exact-match inbound join, a forward-looking lookup, a future-based count, a new-device flag without history, a 30-day sum that includes the current row, an online path that ignores inbound transfers, and a wrong device sequence each make specific tests fail. A leak that only uses the current row (not the future) is invisible to truncation tests and is caught by the unit tests and the DuckDB cross-check, which is why all three exist.

## Phase 9 tests
- `tests/unit/test_explain_unit.py` (20 tests): contributions of one-hot and cyclic columns are summed into the right feature without losing anything, every feature belongs to exactly one unit and has a label, importance by hand (a large effect that cancels out still counts as large), group importance, rank correlation including ties, reason codes (largest risk-raising features in order, scaled by the calibration slope, limited to top k, amount shown once, missing history, empty result keeps its columns), dependence bins (every row in one bin, a common zero gets its own bin, flags and categories as they are), direction (tie-aware, absent for flags), permutation importance (an unused column costs nothing, a group is shuffled with one permutation, reproducible).
- `tests/unit/test_model_card_unit.py` (4 tests): the card reads every number from the saved files (using the same key shapes `run_advanced` writes), and refuses to be written when any of the three files is missing.
- `tests/integration/test_explain.py` (18 tests) on a generated year: contributions add up to the model's log-odds to 1e-8, match the SHAP library (skipped if `shap` is not installed), calibrated effects add up to the calibrated log-odds, `RiskModel.explain` equals the direct computation, is row-independent and needs no labels, refuses a scorer or calibration it cannot explain, flagged transactions get reasons in descending order; the run writes the report, figures and metrics with computed numbers, slices add up and use the same policy, the pattern audit appears only with ground truth; blanking every feature leaves a model with no skill (negative control); a bundle from another split or feature version is refused; the CLI works and fails clearly; explaining never changes the saved model.
- Mutation-checked, each fails a specific test: a column mapped to the wrong feature, reason codes picking the most negative effect, ignoring the calibration slope (in the helper and in the bundle), a group shuffle with a different permutation per column, removing the zero bin, dropping the wrong contribution column, skipping the bundle split check, inverting "flagged", a refit that does not blank the features, and a card that shows validation numbers in the test column. A card-test fixture that guessed the metric key names wrongly first hid a bug (calibration error shown as n/a); the fixture now uses the real key shapes and the integration test checks the real card has no n/a in the scorer rows.
- The explain integration tests add about 50 seconds; the whole suite is about 3 minutes on 2 cores.

## Phase 8 tests
- `tests/unit/test_costs_unit.py` and `tests/unit/test_calibration_unit.py` (30 tests): expected costs by hand, ties go to the less severe action, thresholds move with the amount, realized costs, the oracle, invalid parameters; Platt scaling recovers a known curve, both links, Brier, Wilson and the reliability table.
- `tests/integration/test_advanced.py` (18 tests): LightGBM is deterministic, learns real signal, is chosen on validation, shuffled training labels give no skill, destroying the test part changes nothing fitted or chosen, pickling and text round trips; `assess` needs no labels and changing test labels cannot change a decision; a saved bundle reloads with identical decisions; baselines from another split are refused; report numbers are computed, calibrators are fitted on validation with the right link, figures and files are written, the cost rule beats a fixed cut-off, the sensitivity table is complete, the audit section appears only with ground truth, and the CLI works and fails clearly.
- Mutation-checked, each fails a specific test: choosing the most expensive action, charging the review cost only on fraud, charging the block cost on fraud, using p instead of 1 - p for blocking, ignoring review effectiveness, fitting the calibrator on test data, a wrong calibration link, and decisions that read labels. Two of these first survived and led to a new test, `test_calibrators_are_fitted_on_validation_with_the_right_link`.
- The advanced integration tests add about 60 seconds; the whole suite is about 2.5 minutes on 2 cores.

## Phase 7 tests
- `tests/unit/test_models_unit.py` (19 tests): budget precision/recall on hand-computed cases, exact tie handling (row order cannot change a score), weights equal repeated rows, PR-AUC reference values, customer bootstrap resamples whole customers and is reproducible; matrix shape and column names, rows transformed independently of other rows (stateless), missing values stay missing, unknown categories become all zeros, no labels or identifiers in the matrix; the eight rules, their score, and that they use no labels.
- `tests/integration/test_models.py` (19 tests) on a generated year of data: window order and the 45-day gap, rows inside their window, parts disjoint, every training label known on deployment day, the shortcut split really does use labels not yet known, too-short data raises `SplitError`; imputer statistics come from training rows only; nothing in the test part (labels flipped, amounts scrambled) changes fitting or selection; the selected models equal a fresh fit on the training rows alone; shuffled training labels give no skill; both learned models beat the rules on validation; deterministic fitting; the full run writes report, three figures, models and metadata, and a saved model scores new rows; the audit section appears only with ground truth.
- Mutation-checked: no label gap, fitting on train plus validation, a row-level (instead of customer-level) bootstrap and ignoring ties each make specific tests fail. Using final instead of as-of labels for the correctly gapped training set is not detectable and is not a bug: with a 45-day gap every training label is already known.
- The model integration tests add about 40 seconds; the whole suite is about 2.5 minutes on 2 cores.
