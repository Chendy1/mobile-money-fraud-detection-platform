# Threat model (local scoring API and dashboard)
Scope: the API in `mmrisk.api` and the dashboard running on a developer's own machine with synthetic data. Started in Phase 11, extended in Phase 18 ([security.md](security.md)). It is not a security audit.

| Threat | What exists now | What does not |
|---|---|---|
| Anyone on the network calls the API | Listens on 127.0.0.1 by default; another address needs `--auth-keys`, TLS and `--allow-external` (or `--allow-insecure-external`, which warns). Bearer API keys with roles, per-key rate limit, failure block, audit log (Phase 18) | TLS is uvicorn's own with files you supply; no key expiry; limits are per process and in memory; the container uses the insecure flag and relies on the port being published on 127.0.0.1 |
| Malformed or hostile input | Strict schema (unknown fields, types, allowed values, limits, id pattern), 8 KB body limit, 422 errors that do not echo input | No request rate limit; no check that the customer and device ids are genuine |
| Replay or double submission | Same id and content returns the first answer once; same id with other content is refused | No signature on requests |
| Information leakage | Generic 500 body; request id for the logs; transaction bodies are not logged; the model description exposes only the feature version, the scorer name and the assumed costs | Access logs print the path and status; `/docs` shows the schema unless `--no-docs` |
| Poisoned model file | The loader checks the feature version | Loading uses an allow-list unpickler (a file calling `subprocess` or `os.system` is refused; tested). It is not a sandbox: allowed classes still restore their own state, and it depends on joblib internals. Only load bundles this project created. Signing or a safe format is future work |
| Probing the model by repeated queries | Nothing | The score, the costs and the reason codes together let a caller learn the model; acceptable for synthetic data only |
| Denial of service by large history or many requests | One lock serialises scoring; latency per request is reported in `X-Process-Time-Ms` | Unbounded history per customer; no queue limit; no request timeout inside the API. Phase 19 measured the limit on one 2-CPU machine (see load-testing.md): past about 100 requests/s requests queue for seconds, they are not refused |
| The load generator itself (Phase 19) | `mmrisk.loadtest` sends only to loopback unless `--allow-external`, caps the rate (2000/s) and length (900 s), takes the key from an environment variable, writes no request bodies to reports | It does not check that you own the target; do not point it at a service you do not run |
| Running the service (Phase 20) | Secrets only as files (git- and docker-ignored, scanner refuses them if staged), hashed keys, read-only containers, no capabilities, limits, loopback ports, `preflight` rejects a weaker compose file, `verify` tests the boundaries from outside, backup/restore refuse unsafe archives | Containers never run by the assistant (TO VERIFY); self-signed certificate; image tags not digests, no image scanning; the metrics token is a plain file; anyone who can write the registry folder can change the model; no Alertmanager |
| Reading the metrics | `/metrics` holds counts, timings and the feature version only: no ids, amounts or counties; label values are bounded (route templates, not URLs). Prometheus and Grafana are published on 127.0.0.1; Grafana has no default password, no sign-up and no anonymous access | `/metrics` needs a `metrics` or `admin` key when keys are on (off by default on loopback); no TLS between the containers; Grafana's admin password is passed through an environment variable (Phase 18 would use a secret store); no Alertmanager, so alerts are not delivered to anyone |
| Misuse of the output | Costs are labelled ASSUMED; reason codes describe the model, not a cause | The API must not be used for real decisions about real people |
| Reading the dashboard | Binds to 127.0.0.1 and refuses other addresses without `--password-file` and `--allow-external`; optional shared-password login (scrypt, global lock after 5 failures); usage statistics off; customer ids masked by default; read-only; text from the data is never rendered as HTML (tested) | No TLS, no per-user accounts, no audit of who looked. Masking is a display convenience: whoever can run it or read `data\predictions` sees the ids. Streamlit is a large dependency; `pip-audit` reports (does not block) known issues in transitive packages, see security.md |
