# Feature catalog

Feature set version **1.0**. Generated by `python -m mmrisk.features catalog` from `mmrisk/features/registry.py`; do not edit by hand (a test fails if it is out of date).

All features are computed from the transaction and strictly earlier history. "Earlier" means before the row in (timestamp, transaction_id) order; time windows exclude the row itself and any row with the same timestamp. No feature reads labels or ground truth. All data is synthetic.

| Feature | Type | Group | Looks at | Description |
|---|---|---|---|---|
| `amount_kes` | int | transaction | the transaction itself | Amount in KES. |
| `amount_log` | float | transaction | the transaction itself | natural log of (1 + amount). |
| `transaction_type` | category | transaction | the transaction itself | SEND_MONEY, PAYBILL, ... |
| `channel` | category | transaction | the transaction itself | USSD or APP. |
| `hour` | int | time | the transaction itself | Hour of day, 0 to 23 (local time). |
| `day_of_week` | int | time | the transaction itself | Monday = 1 to Sunday = 7. |
| `is_night` | bool | time | the transaction itself | Hour is 00 to 04. |
| `is_salary_window` | bool | time | the transaction itself | Day of month is 25 to 31 or 1 to 3. |
| `segment` | category | customer | the transaction itself | Customer segment. |
| `account_age_days` | int | customer | the transaction itself | Days since registration. |
| `is_away_from_home` | bool | customer | the transaction itself | County differs from home county. |
| `n_prior_txns` | int | history | the customer's earlier transactions | Earlier transactions by the customer. |
| `secs_since_prev_txn` | float | history | the customer's earlier transactions | Seconds since the customer's previous transaction; null for the first. |
| `txn_count_10m` | int | velocity | the customer's earlier transactions | Earlier transactions in the last 10 minutes. |
| `txn_count_1h` | int | velocity | the customer's earlier transactions | Earlier transactions in the last hour. |
| `txn_count_24h` | int | velocity | the customer's earlier transactions | Earlier transactions in the last 24 hours. |
| `txn_count_7d` | int | velocity | the customer's earlier transactions | Earlier transactions in the last 7 days. |
| `amount_sum_1h` | float | velocity | the customer's earlier transactions | Sum of earlier amounts in the last hour. |
| `amount_sum_24h` | float | velocity | the customer's earlier transactions | Sum of earlier amounts in the last 24 hours. |
| `txn_count_30d` | int | baseline | the customer's earlier transactions | Earlier transactions in the last 30 days. |
| `avg_amount_30d` | float | baseline | the customer's earlier transactions | Mean earlier amount in the last 30 days; null if none. |
| `amount_to_avg_30d` | float | baseline | the customer's earlier transactions | Amount divided by avg_amount_30d; null unless at least 3 earlier transactions in 30 days. |
| `is_new_device` | bool | novelty | the customer's earlier transactions | First time the customer uses this device (and the customer has earlier history). |
| `is_new_recipient` | bool | novelty | the customer's earlier transactions | SEND_MONEY to a recipient the customer never paid before (and has earlier history). |
| `county_changed` | bool | novelty | the customer's earlier transactions | County differs from the previous transaction. |
| `location_jump_1h` | bool | novelty | the customer's earlier transactions | County changed and the previous transaction was under an hour ago. |
| `secs_since_last_inbound` | float | network | other customers' earlier transfers | Seconds since someone last sent this customer money; null if never. |
| `cashout_after_inbound` | bool | network | other customers' earlier transfers | AGENT_WITHDRAWAL within 2 hours of receiving a transfer. |

## Deliberately not features

| Input | Why |
|---|---|
| device_id, counterparty_id, customer_id | identifiers: high cardinality and no meaning across customers |
| merchant or agent fraud rate | target encoding: leaks labels unless built with strict time cut-offs |
| labels, label_available_at, ground truth | the target, never an input |
| global amount percentile | depends on future transactions (a quantile over the whole file) |

## Missing values

Some features are null by design: no earlier transaction (`secs_since_prev_txn`), no earlier activity in 30 days (`avg_amount_30d`), fewer than 3 earlier transactions in 30 days (`amount_to_avg_30d`), or no inbound transfer yet (`secs_since_last_inbound`). A null means "not enough history", which is itself informative, so Phase 7 models must either handle nulls natively (LightGBM) or impute with an indicator (linear models); imputation values are learned from training data only.
